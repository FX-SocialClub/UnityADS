02 — От приложения до запуска

Сначала черновик. Затем явное подтверждение.
  1. Получить и проверить доступ

    Владелец выдает права. Сервер проверяет авторизацию, чтение статистики и нужные операции управления.

  2. Привязать приложение из магазина

    Пользователь передает ссылку на App Store или Google Play. Это привязка приложения к рекламному кабинету, а не публикация APK.

  3. Загрузить креативы

    Добавить рекламные материалы. Проверить формат, требования Unity и статус готовности.

  4. Собрать черновик кампании

    Выбрать приложение, креативы, географию, ставку и бюджет. Проверить настройку атрибуции установок.

  5. Подтвердить бюджет в Telegram

    Бот показывает валюту, тип лимита и параметры. Без подтверждения пользователя сервер не отправляет команду запуска.

  6. Запустить и проверить статус

    Сервер отправляет запрос и сообщает результат. Начало показов зависит от статуса кампании, модерации и доступных средств.

04 — Что проверить перед разработкой

Какой API использовать?

Актуальная точка управления — Advertiser Public API. Прежний Advertising Management API (/advertise/v1) устарел: Unity предлагает миграцию. Доступность нужных методов нужно проверить на выданном кабинете.

Какие права запросить у владельца?

Сервисный аккаунт, идентификатор организации и роли для необходимых операций управления рекламой. Для Statistics API в документации указана роль Advertise Stats API Viewer. Точный набор прав и область доступа согласуются с владельцем организации; названия ролей управления следует сверить с текущим API.

Как сервер получает отчеты?

Планировщик запрашивает Advertising Statistics API, сохраняет расходы и установки, рассчитывает CPI и передает отчет боту. Частота запросов учитывает лимиты API и задержку обновления данных. Ошибка запроса или отсутствие данных не должны превращаться в нулевые расходы.
